## 2. Три вопроса

**2.1. Какое цветовое пространство выбрано для хромакея и почему? Что было бы в RGB?**

Для маски взято HSV. С прямоугольника на синей карточке получились границы H 110–134 и S 92–174, а V оставлен открытым, от 40 до 255: тень того же цвета темнее, но оттенок тот же. В RGB яркость сидит во всех трёх каналах сразу. Те же процентили этого образца дают коридор B 153–209, G 52–127, R 58–135, и доля такой маски 15.94 % против 16.41 % у HSV. Узкий коридор по каждому каналу отрезает более тёмную левую часть карточки так же, как узкий S.

**2.2. Что происходит с гистограммой при γ < 1 и при γ > 1? Куда деваются обрезанные пиксели?**

На `../data/dark.jpg` при γ = 0.5 среднее выросло с 48.2 до 88.5, медиана с 36 до 95, p99 с 162 до 203: масса гистограммы сдвинулась вправо, кадр стал светлее. При γ = 2.0 среднее упало до 18.2, медиана до 5, p99 до 104: масса ушла влево. Белых обрезанных не было ни до, ни после (0.0 %), потолок 255 этот кадр не достаёт. Чёрных было 15.51 %, после γ = 2.0 стало 40.34 %: пиксели, которые формула прижала к нулю, так и лежат в столбике 0, они не пропадают.

**2.3. Почему CLAHE лучше `equalizeHist` на вашем фото — по числам из 1.3? Если не лучше — что измерили и почему?**

На `../data/dark.jpg` CLAHE в тенях не лучше. σ в тенях: исходник 0.5, equalizeHist 19.9, CLAHE 2.3. Среднее в тенях 0.5, 18.4 и 4.1. Тени здесь уже обрезаны в чёрное (15.51 % пикселей с кодом 0, среднее теней 0.5), в клетке CLAHE растягивать нечего. equalizeHist берёт гистограмму всего кадра и поднимает эту кучу. В светах среднее было 124.2, стало 222.7 у equalizeHist и 148.9 у CLAHE.

## 3. Где сломалось

`chromakey` на `../data/object.jpg`, образец `632,572,70,40` на синей карточке. Маска нашла правую часть карточки (рамка 367,186, 738×500, доля 16.41 %), но левая, более тёмная часть с QR-кодом в неё не вошла, а белые буквы остались дырами: дыр 19, после морфологии компонент всё ещё 22. Нижняя граница S получилась 92, этого мало для тёмного синего слева, а закрытие ядром 9 не зашивает штрих буквы. Помог бы образец, в котором есть и тёмный синий, и более крупное закрытие.

## 4. Команды

Всё, что лежит в `../out`, получено этими командами:

```bash
python photolab.py gamma data/dark.jpg --gamma 0.5 -o out/dark_g05.jpg --hist out/dark_g05_hist.png
python photolab.py gamma data/dark.jpg --gamma 2.0 -o out/dark_g20.jpg --hist out/dark_g20_hist.png
python photolab.py wb data/bright.jpg --method grey-world -o out/bright_gw.jpg --hist out/bright_gw_hist.png
python photolab.py wb data/bright.jpg --method white-patch -o out/bright_wp.jpg --hist out/bright_wp_hist.png
python photolab.py clahe data/dark.jpg --clip 2 --tiles 8 -o out/dark_clahe.jpg --compare out/dark_cmp.jpg --hist out/dark_clahe_hist.png
python photolab.py chromakey data/object.jpg --bg data/bg.jpg --sample 632,572,70,40 -o out/object_on_bg.jpg --mask out/object_mask.png
python photolab.py rotate data/poster.jpg --deg 30 -o out/poster_rot30.jpg
python photolab.py resize data/text.jpg --scale 0.25 --report -o out/text_x025.jpg
python photolab.py rectify data/poster.jpg --corners 162.5,645.0,807.8,626.1,896.8,1188.7,95.8,1194.2 --aspect 1.414 -o out/poster_front.jpg
python photolab.py sheet data/*.jpg out/*.jpg --cols 4 -o out/sheet.jpg
```

NumPy и OpenCV. Таблица гаммы, оба баланса белого, размер холста при повороте, порядок углов и раскладка листа написаны своим кодом. Проверено командой `pytest tests -q`.
